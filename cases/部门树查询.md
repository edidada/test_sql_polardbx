# 部门树查询 — PolarDB-X

> MySQL/PG 写法对比见 [../test_sql_mysql8/cases/部门树查询.md](../../test_sql_mysql8/cases/部门树查询.md)。
> 本文档所有 SQL 已在 GitHub Actions 的 PolarDB-X 中实际执行验证。

PolarDB-X（阿里云分布式 MySQL）兼容 MySQL 语法，部门树使用 **`WITH RECURSIVE`**。

## 核心写法（与 MySQL 8 相同）

```sql
WITH RECURSIVE dept_tree AS (
    SELECT id, name, parent_id, 1 AS level
    FROM departments
    WHERE id = 2
    UNION ALL
    SELECT d.id, d.name, d.parent_id, dt.level + 1
    FROM departments d
    INNER JOIN dept_tree dt ON d.parent_id = dt.id
)
SELECT * FROM dept_tree;
```

## PolarDB-X 特有点（分布式视角）

| 项目 | 说明 |
|------|------|
| 拆分表 | 若 `departments` 按 `parent_id` 拆分（`PARTITION BY HASH(parent_id)`），递归 JOIN 每层可能跨分片访问 |
| 复制表 | 建表用 `BROADCAST`（广播表）时递归 JOIN 全部下推到各分片本地执行，树查询性能最好 |
| 递归下推 | PolarDB-X 会把递归 CTE 的锚点+递归部分尽量下推到存储节点（DN），CN 只做结果汇聚 |
| 递归深度 | 与 MySQL 一样有 `cte_max_recursion_depth` 限制 |

## 分布式建表建议

```sql
-- 方案A: 广播表(小表, 树查询最优)
CREATE TABLE departments (
  id INT PRIMARY KEY,
  name VARCHAR(50) NOT NULL,
  parent_id INT NULL
) BROADCAST;

-- 方案B: 按 id 拆分(大表, 数据多)
CREATE TABLE departments (
  id INT PRIMARY KEY,
  name VARCHAR(50) NOT NULL,
  parent_id INT NULL,
  KEY idx_parent_id (parent_id)
) PARTITION BY HASH(id) PARTITIONS 4;
```

## 防死循环

与 MySQL 相同：递归部分 `WHERE dt.level < N`。
